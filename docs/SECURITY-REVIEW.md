# 프론트엔드 보안·안정성 점검

## 적용 사항

- npm 의존성을 호환 범위에서 갱신했습니다. lock 파일도 함께 유지해야 합니다.
- 인증 API 클라이언트는 내부 API 경로만 허용합니다. 외부 절대 URL, baseURL 변경, 경로 이동 및 인코딩 우회를 요청 전에 차단합니다. 검색 조건은 URL 문자열 대신 Axios params로 전달합니다.
- CSRF 토큰은 메모리에 보관하고 POST/PUT/PATCH/DELETE 요청에만 추가합니다. 401 응답이면 사용자 정보와 토큰을 함께 지웁니다.
- 403 응답은 세션 만료와 권한 부족을 구분하도록 세션을 확인합니다. 동시 확인은 하나로 합치며 실패한 변경 요청을 자동 재전송하지 않습니다.
- 회원·상품 변경, 주문 생성 및 입출고는 요청 중 중복 실행을 잠급니다. 이는 브라우저의 실수 방지이며 서버의 멱등성 보장을 대체하지 않습니다.
- 회원과 재고 목록의 이전 응답이 최신 조회 결과를 덮어쓰지 않도록 요청 순서를 검사합니다.
- 회원 등록 창을 닫으면 입력했던 비밀번호를 지웁니다.
- 주문·입출고 수량의 정수 범위를 검사합니다. 서버 검증은 여전히 필수입니다.

## 서버 주소 설정

로컬 기본값은 http://localhost:8080 입니다. 별도 설정 없이 기존 로컬 실행을 유지합니다.
배포 기본값은 현재 페이지의 origin입니다. 별도 API 서버는 VITE_BACKEND_ORIGIN에 HTTPS origin만 지정하고 다시 빌드합니다.
로그인·로그아웃·SSO 주소도 같은 설정에서 가져옵니다.
VITE_ 환경변수는 브라우저에 공개됩니다. 비밀번호, 클라이언트 시크릿을 넣으면 안 됩니다.
다른 출처의 서버를 쓰면 서버의 CORS 및 쿠키 정책도 맞아야 합니다.

## 검증 범위와 한계

- npm test: 경로·origin 검증, CSRF 첨부 및 삭제, 401/403 처리, 세션 확인 병합을 모의 응답으로 검증합니다.
- npm run build / npm run lint: 타입·번들·정적 검사.
- npm audit: 알려진 의존성 취약점 검사. 0건이 모든 취약점 부재를 보장하지 않습니다.
- 이번 점검은 프론트 코드와 자동 테스트 중심입니다. 관리자 실제 세션에서 모든 CRUD 화면을 끝까지 재검증한 것은 아닙니다.
- 서버는 변경하지 않았습니다. 역할·리소스 접근 권한, 입력 검증, HTTPS, Secure/HttpOnly/SameSite 쿠키, CORS, CSRF 검증, CSP 등 배포 보안은 서버·인프라에서 별도로 확인해야 합니다.
- 프론트 메뉴 숨김과 경로 가드는 접근 제어의 보안 경계가 아닙니다. 요청 권한은 반드시 서버가 검사해야 합니다.
- 브라우저 중복 클릭 방지는 다른 탭·새로고침·응답 유실 후 재시도까지 보장하지 않습니다. 주문 중복 방지는 추후 서버 멱등 키 도입 대상입니다.
